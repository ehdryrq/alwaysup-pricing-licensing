## GUI 版、CLT 版、OEM 授权差在哪，该买哪个

GUI 版就是你下载下来双击安装、有窗口可以点的那个。它的能力比「把程序变成服务」这句话听起来要多：程序可以在开机时自启，可以在没人登录的情况下运行，注销登录也不影响；进程崩了会自动拉起来；卡死、CPU 占用飙高、内存吃掉太多这类「假活着」的状态也能识别并重启；可以设定时重启程序甚至重启整台电脑；可以把进程优先级调高；出问题会发邮件通知你；还能挂一个自定义的健康检查脚本定期探测程序是否正常。它甚至会自动点掉「应用程序错误」这类挡住进程退出的系统弹窗。

还有一个容易被忽略的点：AlwaysUp 不需要你开启 Windows 自动登录。有些土办法是让机器自动登录某个账号再靠启动项拉起程序，那等于把密码写在门口。AlwaysUp 走的是服务机制，机器锁屏、无人值守都照常运行。

CLT 版是命令行版本，没有图形界面，配置靠命令完成。适合批量部署几十台机器、或者要塞进自动化脚本里的场景。它的功能和 GUI 版是一套东西，只是操作方式不同。自己用一台机器，没有任何理由选 CLT。

OEM 三档刚才说过了，对象是软件开发者，不是使用者。判断标准只有一条：你是不是要把 AlwaysUp 作为自己产品的一部分卖给客户。不是的话，这一栏和你无关。

所以选择路径很短：个人或小团队，买零售单机 GUI 授权，按你实际要跑的机器数量加份数。机器多就多买几份，官方本来就是按设备计价的。

## 什么情况下值得买，什么情况下别买

该买的人，需求通常很具体：有某个 Windows 程序必须 7×24 挂着，机器重启后它得自己起来，半夜崩了得自己活过来，第二天你还想知道它崩过几次。常见的是自建的小型 Web 服务、数据采集脚本、和业务系统绑定的老式桌面程序、需要长期在线的对接工具。这类场景里，「程序挂了没人知道」造成的损失，远比 37.49 美元贵。

不该买的人也很明确，我直接劝退三类。

第一类，只是想让某个程序开机自动启动一次。Windows 自带的「任务计划程序」免费，配一个登录时触发的任务就完事，不需要买任何东西。AlwaysUp 贵在「挂了自动重启」和「无人登录也能跑」，你用不上这两点，钱就白花。

第二类，程序本身已经是 Windows 服务。很多服务端软件安装完就注册成服务了，天生开机自启、天生后台运行，再套一层 AlwaysUp 是重复劳动。

第三类，预算真的紧，并且能接受没有图形界面。nssm、WinSW 这类开源工具也能把普通程序包装成服务，免费。它们和 AlwaysUp 的差距在附加能力上：崩溃后的自动重启策略、卡死检测、邮件通知、定时重启、优先级调整，这些是 AlwaysUp 收费的理由。如果你只需要「变成服务」这一个动作，开源方案够用，不必为用不到的功能付钱。

还有一类人容易买错：以为自己需要，其实需求在别的系统上。AlwaysUp 只做 Windows，Linux 上的守护进程是另一套东西。
